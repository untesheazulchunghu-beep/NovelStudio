# 作品与工作流 Provider 选择

- 状态：采用
- 日期：2026-10-02
- 范围：M4 作品默认 Provider、任务选择与工作流节点 Provider

## 背景

Provider 目录已经支持多个模型服务商，但创作任务目前只使用任务请求中的 Provider，空选择会直接落到全局默认值。作品需要能够固定常用服务商，工作流也需要让不同生成或审稿节点使用不同服务商。任务排队后还必须保留当时的选择，避免之后修改作品默认值或工作流定义改变重试行为。

## 决策

- Provider 按以下优先级解析：显式工作流节点 Provider、显式任务 Provider、作品默认 Provider、全局默认 Provider。较高优先级有值时，不读取较低优先级。
- 作品默认 Provider 保存在 `novels`，空值表示继承全局默认。作品创建时默认继承全局默认；作品设置可随时切换到继承或任一现存 Provider。
- 工作流节点的 `providerId` 是可选项，只对 `generate` 和 `review` 节点生效。未单独指定时继承任务最终 Provider。资料和输出节点不调用模型，不选择 Provider。
- 保存作品默认值和工作流定义时验证 Provider 存在。运行工作流时再次验证节点 Provider；若已被删除，拒绝启动并提示更新工作流，不静默替换成其他服务商。
- 创建任务时将任务 Provider 和每个工作流节点解析后的 Provider ID 写入任务请求快照。失败重试沿用该快照；若快照引用的 Provider 已被删除，则重试失败并要求用户显式选择有效 Provider 后重新创建任务。
- 自动生成章节记忆使用最终产出正文的 `generate` 节点 Provider；非工作流生成沿用任务 Provider。任务用量仍按每次调用实际使用的 Provider 计费。
- 手动刷新章节记忆沿用作品默认 Provider；本次显式任务选择不影响独立发起的刷新操作。

## 结果

作品可以设定稳定的模型默认值，单次任务可覆盖作品设置，工作流节点可再细化覆盖。任务快照保留解析后的选择，能够解释用量并让重试使用同一组 Provider ID。被删除的显式配置会导致明确的启动或重试错误，而不会暗中切换服务商。
