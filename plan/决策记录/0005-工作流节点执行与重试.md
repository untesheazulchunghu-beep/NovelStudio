# 工作流节点执行与重试

- 状态：已实现
- 日期：2026-10-04（M2 完成）
- 范围：工作流按节点逐个执行、审稿退回和失败重试

## 背景

早期工作流只是把所有节点拼成一段提示词，一次性调用模型。这导致：
- 无法让生成和审稿使用不同模型
- 审稿无法退回修改
- 失败后无法只重试失败节点

M2 改为真正的节点级执行引擎。

## 决策

### 节点类型
- `context`：资料节点，文本直接传递给下游，不调用模型
- `generate`：生成节点，调用模型生成内容
- `review`：审稿节点，调用模型评审，输出通过/不通过
- `output`：输出节点，根据作品审核模式决定是否自动写入正文

### 执行顺序
- 按节点依赖关系拓扑排序
- 每个节点看到上游节点的输出
- `review` 节点不通过时，退回前一个 `generate` 节点
- 最多退回 2 次，再失败任务标记为失败

### 任务快照
- 创建任务时将工作流节点和解析后的 Provider ID 写入 `request_json`
- 失败重试时从快照恢复工作流定义
- 已成功节点从快照中跳过，只重跑失败节点

### 事件记录
- `task.node_start`：节点开始执行
- `task.node_success`：节点成功完成
- `task.node_failed`：节点失败（含错误信息）
- `task.chapter_review_feedback`：审稿不通过的反馈内容
- 取消任务时停住当前节点，不启动后续节点

### 输出节点行为
- 人工审核模式：留下待审核提案，不改正文
- 自动写入模式：直接更新正文，保留历史版本
- 演示模式：强制留下待审核提案（防止占位文本污染正文）

## 结果

- 工作流真正按节点执行，而非单次拼接
- 审稿可退回生成节点，形成修改循环
- 失败重试只重跑失败节点，节省 Token
- 节点级事件可追溯执行过程

## 验证

`internal/novel/workflow_run_test.go` 覆盖：
- 节点按顺序执行，后一个节点看到前一个结果
- 审稿不通过退回生成，最多 2 次
- 取消任务停住当前节点
- 失败重试只重跑失败节点

## 与其他任务类型的关系

- 批量生成任务：不走工作流，每章单次调用
- 审稿清单任务（`review` kind）：独立任务，不走工作流节点
- 连续性检查任务（`continuity` kind）：独立任务，不走工作流节点

工作流 `review` 节点只做通过/不通过分支，不是关键事件逐条核对的审稿清单。
