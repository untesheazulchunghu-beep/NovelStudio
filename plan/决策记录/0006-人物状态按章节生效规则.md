# 人物状态按章节生效规则

- 状态：已实现
- 日期：2026-10-04（M3 完成）
- 范围：结构化人物状态、章节关联和软删除处理

## 背景

知识图谱的人物节点只有静态描述，无法表达人物在故事进程中的动态变化（称谓、年龄、能力、立场）。需要一个按章节维护人物状态的机制，让生成和连续性检查能看到"截至目标章节时人物的状态"。

## 决策

### 数据结构
- `character_states` 表关联人物图谱节点（`character_id`）和章节（`chapter_id`）
- 每条记录包含：称谓、年龄、能力、立场、补充说明
- 允许同一人物在不同章节有多条状态记录

### 生效规则
- 生成或检查目标章节时，选择该人物在目标章节号及之前最近的状态
- 按 `chapter_number` 倒序、`character_states.id` 倒序排序，取第一条
- 软删除章节的状态暂停生效，恢复后重新纳入

### 查询范围
- 只注入蓝图点名的人物状态（与 `AssembleChapterContext` 的实体匹配逻辑一致）
- 连续性检查按当前正文中出现的人物选择状态

### 生命周期
- 编辑者在人物图谱节点下按章节手动维护状态
- 删除人物节点时级联删除其状态记录
- 删除章节时状态记录保留，但查询时跳过
- 恢复章节后状态重新生效

### 上下文注入格式
```
人物状态（第X章生效）：张三
称谓：少年侦探
年龄：17岁
能力：推理、观察
立场：正义
补充：刚获得侦探资格证
```

## 结果

- 人物状态随故事进展动态更新
- 生成和连续性检查能看到时间线正确的人物状态
- 软删除章节的状态暂停，不会污染后续章节
- 状态来源可追溯（标明生效章节号）

## 验证

`internal/novel/character_state_handlers.go` 实现 CRUD 接口  
`internal/task/memory.go` 的 `characterStatePieces` 按章节选择状态  
软删除章节场景已由删除恢复测试覆盖

## 限制

- 当前需手动维护状态，不会从章节记忆自动提取
- 删除章节后重新恢复，章节号可能变化，状态关联仍按 `chapter_id`
- 未实现"从某章节复制状态到另一章节"的便捷操作
