## 二、P0：数据安全与正确性

### 1. 演示模式的文本会被「自动写入」写进正文（已修复）

- 位置：`backend/internal/llm/provider.go`、`backend/internal/task/manager.go`
- 原问题：未配置 `LLM_API_KEY` 时，生成器返回固定的演示文本；旧实现会在 `auto` 模式下将占位内容直接写入正文。
- 当前状态：任务管理器通过生成器的演示模式标记识别无密钥模式；演示产出始终保存为待审核提案，不自动改动正文。任务事件带有 `demoMode`，前端任务面板提示这是演示内容。
- 边界：演示标记目前附着在任务事件与运行中的任务提示上，提案记录本身尚未持久化该标记；不应把演示提案当作真实生成结果。

### 2. 同一批次内后一章看不到前一章的新内容（已修复）

- 位置：`backend/internal/novel/task_handlers.go`、`backend/internal/task/manager.go`
- 原问题：`PreviousTail`（上一章结尾 600 字）在任务创建时从数据库读取一次，批量生成相邻章节时后一章只能看到前一章的旧正文。
- 当前状态：任务按顺序执行时，若两章在本批次中相邻，后一章改用前一章刚生成的内容作为承接文本；第一章以及章节号不连续的情况仍使用任务创建时读取的正文结尾。
- 验证：回归测试断言第二章提示词包含第一章的新产出、不含旧结尾。

### 3. 任意一章失败会终止整批任务，且无法续跑（已修复）

- 位置：`backend/internal/task/manager.go`、`backend/internal/novel/task_handlers.go`、`backend/internal/novel/server.go`
- 原问题：单章生成失败会立即终止整批任务，后续章节不执行，服务重启后中断任务也没有恢复入口。
- 当前状态：任务事件记录章节排队、开始、完成、失败或取消；单章失败后仍继续处理后续章节。失败 / 中断 / 取消任务可通过 `POST /api/v1/tasks/{taskID}/retry` 新建重试任务，只处理原任务中没有成功提案的章节；成功章节不会重复生成。任务快照随新任务持久化，旧数据库通过列迁移兼容。
- 边界：部署升级前创建的历史任务没有请求快照，无法自动恢复；这类任务接口会提示重新发起生成。每个任务只能创建一个直接重试任务，但重试任务失败后可以继续重试。
- 验证：回归测试覆盖单章失败后继续、只重试未成功章节、成功提案不重复，以及旧数据库迁移。

### 4. 会话为无状态签名，无法服务端吊销（已补最小能力）

- 位置：`backend/internal/auth/session.go`
- 当前状态：Cookie 带 `session_version`，登出会递增版本并吊销该账户所有设备上的旧会话；旧数据库自动迁移，已覆盖跨设备吊销测试。
- 边界：当前没有修改密码、找回密码或邮箱验证接口；开发环境未设置 `SESSION_SECRET` 时重启仍会使所有人重新登录。

## 三、P1：核心写作体验

### 5. 工作流已按节点执行（M2 已完成）

- 位置：`backend/internal/task/workflow.go`、`backend/internal/novel/task_handlers.go`
- 现状：工作流按依赖顺序逐个执行。资料节点不调用模型；生成和审稿节点各自调用，后一个节点能看到前一个结果。审稿不通过会退回前一个生成节点，最多 2 次，再失败会停在任务上。输出节点按人工审核、自动写入或演示模式保存正文。任务事件记录每个节点的开始和结束；取消停住当前节点；生成器报错后只重试失败节点。
- 节点选择模型已实现；仍未做全文检索 / RAG（M5）。关键事件清单、独立连续性提示和结构化人物状态已完成。工作流 `review` 节点的通过 / 不通过不是这两项审稿。

### 6. 上下文注入已按章节记忆、相关图谱和预算收口（M1 已完成）

- 位置：`backend/internal/task/memory.go`、`backend/internal/novel/task_handlers.go`
- 现状：定稿（应用提案或自动写入）后保存摘要、出场人物、新增设定和伏笔变化。生成时注入近 8 章摘要、蓝图点名的人物与地点及其关系、目标章节适用的最新人物状态，以及尚未回收的相关伏笔，并按 `CONTEXT_BUDGET_RUNES` 把额度分给这些部分。任务详情同时列出注入项和未注入项。上一章结尾 600 字仍然用于相邻承接。已不再按 kind/label 盲取前 80 个实体和前 160 条关系。
- 仍未做：全文检索、FTS 与嵌入（M5）。节点级执行已在 M2 完成。长篇里和蓝图用词对不上的人物仍不会自动进入本次上下文；人物状态沿用蓝图相关实体的选择结果。

### 7. 模型接入过于简陋

- 位置：`backend/internal/llm/provider.go`、`backend/internal/config/config.go`
- 现状：
  - Provider 配置是本机全局共享的多 Provider 目录；任务、作品默认值和工作流生成 / 审核节点都可指定 Provider。
  - 温度、最大输出长度与超时已可配置，临时网络错误、限流和上游 5xx 会有限重试，并向用户返回分类提示。
  - 系统提示词仍写死；没有按任务记录 token 用量与费用。
  - 非 JSON 流片段仍会跳过；已识别 SSE 错误事件并避免向用户暴露上游原文。
- 后续改进：模型配置入库、密钥加密、多供应商、任务用量、作品默认值、节点模型选择和可用模型列表已落地；仍需 Provider 能力检测与提示词模板管理。

### 8. Token 事件逐条写入 SQLite（已优化）

- 位置：`backend/internal/task/manager.go`
- 当前状态：token 事件按约 150ms / 4 KB 合并，序号从内存计数并在启动时回填；启动时清理 30 天前已结束任务的 token 事件，其他事件保留用于回放。
- 验证：600 个短增量明显合并，事件序号递增且回放文本完整；清理测试确认不会删除任务终态事件。

### 9. 提案审核体验不足

- 位置：`backend/internal/novel/task_handlers.go`、`frontend/src/App.vue`
- 现状：提案按段落组显示差异，可选择采纳部分段落组或整份提案，标题可单独采纳；服务端重算所选段落组并按章节版本锁应用。过期提案可查看基准、当前和提案正文，所有者 / 编辑可手工整理合并稿；服务端要求合并预览中的当前版本仍然最新，并保留合并前版本。找不到提案基准版本时提示基于最新版重新生成。`reviewer` 仍可审核非过期提案，手工合并要求编辑权限。
- 后续改进：补充浏览器级 diff / 合并冒烟测试，并验证冲突和并发更新提示。上述选择性采纳与手工合并实现已加入，当前尚未跑构建或回归检查。

### 10. 内容管理能力缺失

- 位置：`backend/internal/novel/server.go`（路由表）
- 现状：
  - 知识实体与关系支持编辑 / 删除；作品与章节支持软删除、回收站恢复；工作流支持永久删除；章节支持事务内排序。
  - TXT / Markdown / EPUB / DOCX 导出已实现，并有 HTTP 测试覆盖压缩包结构、顺序、中文、软删除章节与非法格式；全文语义检索仍缺失。
  - 编辑器实时字数（去空白后的字符数）已由纯函数覆盖；没有按章 / 按作品 / 按日的统计与写作目标。
  - 编辑器已有按章节/版本缓存的本地草稿、刷新前保护和 2.5 秒防抖服务端自动保存；使用 `expectedUpdatedAt` 检测正文与蓝图并发修改。选择章节会恢复对应草稿；非冲突的保存失败保留本地草稿；版本冲突同时保留本地草稿和服务器快照，只有明确确认后才覆盖服务器章节。当前还支持专注写作模式、Escape 退出、Ctrl/Cmd+S 保存和动态字数播报。这三项由 `frontend/src/draft.ts` 的 `node:test` 覆盖。
  - 仍缺按日写作统计和全文语义检索。

### 11. 审稿与连续性提示

- 现象：已有独立审稿任务，按关键事件的非空行给出已完成 / 未完成 / 待核实，并把模型判断和逐字引文核对分开保存。它不改正文，也不产生章节提案。工作流 `review` 节点仍只做通过 / 不通过分支，不是这项任务。
- 参考：`ck/AI-Novel-Writer-master/docs/plans/chapter-goal-review-production.md`（逐项目标审稿）、`ck/luobi-ai-writing-main/src/services/narrative-consistency`。
- 连续性检查已完成：独立任务按当前正文选择相关图谱事实和已定稿记忆，报告时间线、人物状态或设定冲突提示，并分别标出当前正文与来源引文是否逐字可核对；只供作者参考，不修改正文、不生成提案。
- 结构化人物状态已完成：编辑者可在人物图谱节点下按章节维护称谓、年龄、能力、立场与补充说明。生成和连续性检查会按目标章节选择截至当章最近的状态；章节软删除时状态暂停生效，恢复后重新启用。

## 四、P2：工程质量

### 12. 前端单文件过大，缺少测试与 lint

- 位置：`frontend/src/components/` 中的登录、作品库、章节编辑器、知识图谱、工作流、成员管理页面，以及 `frontend/package.json`
- 现状：登录、作品库、章节编辑器、知识图谱、工作流、成员管理已各自拆为 Vue SFC，并由 `App.vue` 组合；提案审核、任务面板、回收站和模型设置仍是独立面板。HTTP 调用在 `frontend/src/api.ts`。`node:test` 覆盖段落 diff、关键 API、草稿决策、字数统计和工作流连线。ESLint 与 Prettier 检查 `frontend/src`，并进入 CI。
- 后续改进：评估 Vue Router / Pinia；浏览器级测试（Playwright）仍待后续，不在当前工程底线内。

### 13. 数据库迁移方式过于原始

- 位置：`backend/internal/database/db.go:36-83`
- 现象：schema 通过 `strings.Split(schema, ";")` 逐条执行，依赖语句内部不含分号；迁移只支持「缺列就 `ALTER TABLE ADD COLUMN`」，无法表达改列、建索引变更、数据回填，也没有版本号与回滚。
- 改进：引入带版本号的迁移表（`schema_migrations`）与按序迁移文件；迁移前自动备份数据库文件。

### 14. 缺少备份、部署与 CI

- 现象：根目录已有 MIT `LICENSE`，工作区已是 git 仓库，`.gitignore` 排除 `ck/`、`backend/data/`、`frontend/node_modules/`、`frontend/dist/`、`release/` 与 `backend/.env`。GitHub Actions 已检查后端 `go vet` / `go test` 与前端测试、lint 和构建。本机打包脚本与 SQLite 在线备份工具已提供。尚未提供 Dockerfile，也还没有推送到远程。
- 改进：Dockerfile 与跨平台安装包仍待评估；不在当前完成范围内。

### 15. 可观测性与限流范围有限

- 现象：日志为标准库 `log` 纯文本，无请求 ID；仅认证接口限流，生成接口没有按用户的并发 / 频率限制（全局并发仅 2，由 `manager.go` 的 `semaphore` 控制，一个用户可占满）；没有指标与审计日志（谁在何时应用了哪个提案）。
- 改进：结构化日志（`log/slog`）+ 请求 ID；按用户的生成配额与排队可见性；关键写操作审计。

### 16. 文档与规范

- 现象：没有 `CONTRIBUTING`、架构决策记录；API 无 OpenAPI 描述。README 功能概览已按当前实现写明章节记忆，以及按节点执行的工作流。
- 改进：参考 `ck/AI-Novel-Writer-master/docs/adr` 建立 ADR；维护 `docs/api` 或 OpenAPI；README 与实现保持一致。
